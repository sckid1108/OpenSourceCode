Overview

One driver for the whole EMC230x family. It identifies the part from its product ID, touches only the fan channels that part implements, and speaks RPM rather than raw tachometer counts.

The driver performs no platform calls of its own. You supply two function pointers — an SMBus register read and an SMBus register write — and everything else is portable C++. There is no dynamic allocation, no exceptions, no RTTI, and no dependency beyond <stdint.h> and <stdbool.h>.

What it handles for you

  • Device detection. The product ID is read once on first use and the per-fan register accesses are masked to the channels that exist. Registers belonging to an absent fan are reserved, and reading them is a real source of trouble on the smaller parts.
  • Tachometer arithmetic. The 13-bit count, its register justification and the RPM conversion are all internal. You pass and receive RPM.
  • Error reporting. Every operation returns a status. A missing transport, a bad argument and a bus failure are distinguishable, and none of them are fatal.
  • Cached state. Each getter refreshes an internal mirror of the device registers, readable through getCachedState().

What it deliberately leaves to you

  • The I²C/SMBus implementation, including timeouts and bus recovery.
  • Thread safety. The driver holds mutable cached state and is not re-entrant; serialise access yourself if more than one context uses it.
  • Any policy above the chip — thermal curves, fault escalation, hysteresis.

Supported devices

All four parts share one register map; they differ only in how many fan channels are populated. The driver reads the product ID and builds a channel mask from it.

EMC230220x360x03EMC2302_ID
EMC230330x350x07EMC2303_ID

The manufacturer ID register always reads 0x5D. Checking it is the cheapest way to confirm you are talking to the part at all rather than to a floating bus.

Default address

The SMBus address is 0x2F on the EMC2301 and EMC2302. The EMC2303 and EMC2305 have an ADDR_SEL pin and can sit elsewhere — pass the real address to setI2CDriver(), which the driver uses for every transaction.

Quick start

Four steps from a blank project to a fan turning at a commanded speed.

  1. Provide the transport

    Two free functions wrapping your platform's SMBus register access. Return 0 on success and anything non-zero on failure.

    int smbus_read(uint16_t addr, uint8_t cmd, uint8_t *data, uint8_t len)
{
    return (int) HAL_I2C_Mem_Read(&hi2c2, (addr << 1), cmd,
                                  I2C_MEMADD_SIZE_8BIT, data, len, 100);
}

int smbus_write(uint16_t addr, uint8_t cmd, uint8_t *data, uint8_t len)
{
    return (int) HAL_I2C_Mem_Write(&hi2c2, (addr << 1), cmd,
                                   I2C_MEMADD_SIZE_8BIT, data, len, 100);
}

  2. Install it

    The address you pass here is used for every subsequent transaction.

    EMC230X::EMC230X fan;
fan.setI2CDriver(0x2F, smbus_write, smbus_read);

  3. Confirm the device

    Optional — the bulk getters identify the part themselves on first use — but doing it explicitly gives you somewhere to handle a wiring fault.

    if (fan.getChipInfo() != EMC230X::EMC230X_STATUS_OK ||
    fan.getManufacturerID() != EMC230X::MICROCHIP_MANUFACTURER)
{
    // nothing on the bus at this address
}

  4. Command a speed and read it back

    runControlAlgorithm() configures closed-loop control and sets the target in one call. Pass 0 to park the fan.

    fan.runControlAlgorithm(EMC230X::FANCNTRL_1, 2000);   // 2000 RPM

uint16_t rpm = 0;
fan.getFanTachReading();                              // refresh the cache
fan.getFanRPMReading(EMC230X::FANCNTRL_1, &rpm);

SMBus transport

The driver calls out through two function pointers with identical signatures:

typedef int (*smbus_write_register)(uint16_t addr, uint8_t cmd, uint8_t *data, uint8_t len);
typedef int (*smbus_read_register) (uint16_t addr, uint8_t cmd, uint8_t *data, uint8_t len);
ParameterMeaning
addrThe device's 7-bit SMBus address, exactly as passed to setI2CDriver(). Shift it left yourself if your HAL expects an 8-bit address.
cmdRegister address (the SMBus command code).
dataBuffer to fill or send.
lenByte count. The driver only ever asks for one byte at a time; multi-byte registers are read as two separate single-byte transactions in the order the datasheet requires.
return0 for success, non-zero for failure. The value is not interpreted — any non-zero result becomes EMC230X_STATUS_FAIL.
Blocking calls

Every driver call is synchronous and runs to completion on your transport. A full getChipState() is on the order of a hundred transactions on a five-fan part. Call it during initialisation or on a slow cadence, not from a tight control loop.

Status & errors

Every operation that can fail returns EMC230X_STATUS. The values are bit flags, not an ordered list.

ValueBitMeaning
EMC230X_STATUS_OK0Success.
EMC230X_STATUS_FAIL0x01An SMBus read or write returned non-zero.
EMC230X_STATUS_INVALIDARG0x02A fan selector that is not exactly one channel, or a null out-pointer.
EMC230X_SMBUS_DRIVER_NULL0x04setI2CDriver() has not been called.
Never test with ==

getChipState() ORs together the result of every read it performs, so it can return 3, 5, 6 or 7 — values that match no single enumerator. Test == EMC230X_STATUS_OK for "everything succeeded", or use & to isolate one cause. Comparing == EMC230X_STATUS_FAIL will silently miss combined failures.

// correct
if (fan.getChipState() != EMC230X::EMC230X_STATUS_OK) { /* something failed */ }
if (st & EMC230X::EMC230X_SMBUS_DRIVER_NULL)          { /* transport missing */ }

// wrong -- misses 3, 5, 7
if (st == EMC230X::EMC230X_STATUS_FAIL) { }

Tach counts & RPM

The device does not report speed. It reports the number of 32.768 kHz clock periods that elapse across a fixed number of tachometer edges — a period, not a frequency. Speed is the reciprocal, which is why a slower fan produces a larger count.

The conversion

Datasheet equation 4-2 in full:

              1        (n - 1)
RPM  =  ───────────  ×  ─────────────  ×  f_TACH  ×  60
           poles        COUNT × (1/m)
TermMeaningTypical
polesTachometer pulses per revolution.2
nEdges sampled. Must equal 2 × poles + 1.5
mRange multiplier, from the RNG field.1
f_TACHTachometer clock.32768 Hz
COUNTThe 13-bit value in the TACH reading register.—

For a standard 4-wire fan at multiplier 1 this collapses to equation 4-3, which is what the driver implements:

RPM = 3932160 / COUNT          COUNT = 3932160 / RPM
RPMCountHigh byteLow byte
50007860x180x90
40009830x1E0xB8
300013100x280xF0
200019660x3D0x70
150026210x510xE8
100039320x7A0xE0
48081910xFF0xF8

The count saturates at 0x1FFF. At multiplier 1 that corresponds to roughly 480 RPM, which is the slowest speed the device can measure — the figure the datasheet quotes as the bottom of its 480–16000 RPM tachometer range. Anything slower, including a stopped fan, pins there.

Register justification

The 13-bit count is left-justified across its two registers. The low byte carries the least significant five bits in positions 7:3, and bits 2:0 are unimplemented.

If you extend the driver

Keep the shift welded to the byte assembly for each fan. Applying it after reading all channels means a transport failure part-way through leaves the fans already read scaled by a factor of eight — a wrong speed rather than an error.

Poles versus pulses

The datasheet's word "poles" means tachometer pulses per revolution, not the motor's magnetic pole count. A standard 4-wire fan emits two pulses per revolution and is therefore a "2-pole" fan in the device's vocabulary — regardless of how many magnetic poles the motor has. Most 40 mm fans are 4-pole motors emitting 2 pulses/rev, and the correct setting for them is FANPOLE_2.

Common mistake

Selecting FANPOLE_4 because the datasheet for a 4-pole motor says "4 poles" makes every reading half the true speed. The edges sampled must satisfy n = 2 × poles + 1; with a 2-pulse/rev fan and 9 edges the device measures four revolutions but assumes two.

Range selection

The FRNG field trades measurement resolution against the slowest speed that fits in 13 bits.

FRNGMultiplierNominal minimumSlowest measurableResolution @ 5000 RPM
00×1500 RPM480 RPM≈ ±6 RPM
01×21000 RPM960 RPM≈ ±3 RPM
10×42000 RPM1920 RPM≈ ±1.5 RPM
11×84000 RPM3840 RPM≈ ±0.8 RPM

Microchip's guidance is to pick the largest range below your fan's minimum speed. In practice the error window (ERG, typically 50 RPM) is far wider than the quantisation at any setting, so resolution is rarely the binding constraint. Dropping below the slowest measurable speed is: the count overflows and the device reports a stall, triggering spin-up retries. FRNG = 00 is the safe default unless you have a specific reason otherwise.

Control modes

Each fan channel is independently in one of two modes, selected by the ENAG bit via toggleControlAlgorithm().

Closed loop (ENAG = 1)Direct setting (ENAG = 0)
You setA target tachometer count — i.e. a speed.A PWM duty cycle, 0–255.
Device doesRuns a PID loop against the measured tach, correcting for load, voltage and fan ageing.Nothing. The duty is applied as given.
Drive registerRead-only. Writes are ignored.Writable via setFanDriveSettings().
Ramp controlAlways active, governed by max step and update time.Only if ENRC is set.
Use whenYou want a speed held accurately.You want a duty cycle, or the fan has no usable tach.
Stopping a fan

In closed loop, writing a target of 0x1FFF — which is what runControlAlgorithm(fan, 0) does — drives the output to 0%. Any other target restarts the spin-up routine.

API reference

All types live in namespace EMC230X. Functions returning EMC230X_STATUS report EMC230X_SMBUS_DRIVER_NULL if no transport has been installed, and EMC230X_STATUS_INVALIDARG if the fan selector is not exactly one channel.

Setup

EMC230X(); EMC230X(uint8_t addr, smbus_write_register write_func, smbus_read_register read_func);

The default constructor initialises the cache only — no bus activity occurs, and none will until a transport is installed.

void setI2CDriver(uint8_t addr, smbus_write_register write_func, smbus_read_register read_func);

Installs the transport and the device address. Must be called before anything else. The address given here is used for every transaction.

Identification

EMC230X_STATUS getChipInfo();

Reads the product features, product ID, manufacturer ID and revision registers, and builds the available-fan mask. Called automatically by the bulk getters on first use.

EMC230X_PRODUCTID getChipID(); EMC230X_MANUFACTURERID getManufacturerID(); uint8_t getChipRev(); uint8_t getProductFeatures(); uint8_t getAvailableFans();

Cached accessors, valid after getChipInfo(). No bus activity. getAvailableFans() returns a bit mask of EMC230X_FAN values.

const sEMC230X_State &getCachedState() const;

Read-only view of every register value the getters have cached. Freshness is entirely determined by which getters you have called.

Packed struct

sEMC230X_State is declared packed. Read its 16-bit members by value; taking their address can yield an unaligned pointer, and an unaligned 16-bit access faults on Cortex-M0/M0+.

Tach & RPM

EMC230X_STATUS getFanRPMReading(EMC230X_FAN fan, uint16_t *rpm); EMC230X_STATUS getFanRPM (EMC230X_FAN fan, uint16_t *rpm);

Both report speed through rpm and the outcome through the return value, so a stopped fan stays distinguishable from a failed read:

Return*rpmMeaning
OK> 0Measured speed.
OK0Count at full scale — the fan is stopped or disconnected.
FAIL0The cache was never populated, or a read failed.
INVALIDARG0Bad fan selector, or a null pointer.

getFanRPMReading() is integer arithmetic over the cached count and performs no bus traffic — call getFanTachReading() first to refresh. getFanRPM() is the floating-point equivalent and re-reads configuration and all tach registers on every call, roughly fifteen transactions. Prefer the former in a control loop; the two agree to within one RPM.

uint16_t getFanTachReading(EMC230X_FAN fan); uint16_t rpmToTachCount(uint16_t rpm); EMC230X_FANPOLES getFanPoles(EMC230X_FAN fan);

Cached accessors and the conversion helper. rpmToTachCount() returns 0x1FFF for 0 RPM (fan off) and clamps anything below the measurable minimum.

High level

void runControlAlgorithm(EMC230X_FAN fan, uint16_t targetRPM);

Configures a channel for closed-loop control and commands a speed, in one call. Applies a complete working configuration for a standard 4-wire fan: 2 pulses/rev, range multiplier 1, 400 ms update interval, 50 RPM error window, basic derivative, glitch filter on, open-drain output at 26 kHz. Pass targetRPM = 0 to park the fan.

Speeds below the measurable minimum are clamped. This is a convenience wrapper — for anything unusual, drive the individual setters yourself.

Worked example

A 40 mm 4-wire fan — 5000 RPM maximum, 2 tachometer pulses per revolution, stopping at 0% PWM — under closed-loop control.

EMC230X::EMC230X fan;
fan.setI2CDriver(0x2F, smbus_write, smbus_read);

if (fan.getChipInfo() != EMC230X::EMC230X_STATUS_OK ||
    fan.getManufacturerID() != EMC230X::MICROCHIP_MANUFACTURER)
{
    return; // no device on the bus
}

// One call applies a complete working configuration and the target.
fan.runControlAlgorithm(EMC230X::FANCNTRL_1, 2000);

// Later, in the control loop -- one bus burst, then arithmetic only.
if (fan.getFanTachReading() == EMC230X::EMC230X_STATUS_OK)
{
    uint16_t rpm = 0;

    if (fan.getFanRPMReading(EMC230X::FANCNTRL_1, &rpm) == EMC230X::EMC230X_STATUS_OK)
    {
        // rpm == 0 here means genuinely stopped, not a read failure
    }
}

fan.runControlAlgorithm(EMC230X::FANCNTRL_1, 0);   // park the fan

Pitfalls

A stopped fan reads 8191, not 0

The count is a period. No tachometer edges means the counter runs to full scale. Treat 0x1FFF as "not turning" — which is exactly what the RPM accessors do, reporting 0 RPM with an OK status.

The drive register is read-only in closed loop

setFanDriveSettings() silently has no effect while ENAG = 1. Call toggleControlAlgorithm(fan, false) first if you want direct duty control.

Software lock survives until power cycle

If the lock bit is set, every write is silently ignored and no error is reported — the bus transaction succeeds. Check it before concluding your configuration is not taking.

Minimum drive too low will stall the loop

If the PID can command a duty below the one at which the fan stops turning, it will — then chase a fan that is no longer moving, trigger spin-up, and oscillate. Set setFanMinDrive() from a measured duty sweep rather than a guess.

Fan alerts while intentionally stopped

A fan parked on purpose still trips the stall and spin-up status bits and asserts ALERT. Clear that channel's interrupt enable before stopping it, or gate your handler on your own "commanded off" state.

Reserved registers on smaller parts

The fan 3–5 registers do not exist on an EMC2301 or EMC2302. This driver masks them automatically once the part is identified. If you extend it, preserve that — and never let a partial read leave earlier channels holding an unshifted count.
